# BallTrack — сервис отрисовки траекторий пасов (волейбол)

FastAPI-сервис: загружаете волейбольное видео → получаете
* трек мяча (нейросетевой детектор **VballNet**, ONNX, окно из 9 кадров),
* сегментацию на розыгрыши (эпизоды видимости мяча + фазы по сторонам сетки),
* детекцию **пасов** = параболических (баллистических) участков траектории,
  летящих **влево/вправо К сетке** (полёты «от сетки» — атака/отбой — пасами
  не считаются),
* метрики каждого паса (time-of-flight, apex, дальность, v0),
* **видео с отрисованными траекториями пасов поверх исходного** (шлейф за
  мячом, дуга, маркеры RELEASE/CATCH, стрелка направления, HUD).

## Почему раньше мяч «почти не детектился», а пас не отличался от не-паса
Старая схема: COCO-YOLO (`yolo11n`, класс 32 "sports ball") + SORT + эвристика
«пас = полёт между контактами с боксами игроков». На реальных игровых видео
COCO-YOLO ловит маленький/размытый мяч в единицах процентов кадров, а
контактная эвристика объявляет пасом любую подачу/атаку/отбой.

Новая схема:
1. `app/services/vballnet.py` — детектор VballNet из
   [asigatchov/fast-volleyball-tracking-inference](https://github.com/asigatchov/fast-volleyball-tracking-inference)
   (веса `models/VballNetFastV1_seq9_grayscale_233_h288_w512.onnx`). Модель
   принимает 9 полутоновых кадров 512×288 и возвращает 9 тепловых карт;
   постпроцессинг как в оригинале (порог → контур → центроид). Замер на
   реальном видео: **~87% кадров с детекцией**.
2. `app/services/pass_detector.py` — розыгрыши по разрывам видимости; внутри
   скользящим окном ищутся участки, удовлетворяющие модели свободного полёта
   `x(t)=x0+vx·t`, `y(t)=y0+vy·t+½g·t²` (LSQ-фит, RMSE- и гравитационный
   фильтры). Участок «к сетке слева/справа» = пас; «от сетки» = не пас.
3. `app/services/renderer.py` — отрисовка траекторий поверх видео.

## API
| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/v1/videos` | загрузить видео (multipart), создать job, запустить анализ |
| GET | `/api/v1/jobs` / `/api/v1/jobs/{id}` | список/статус задач |
| GET | `/api/v1/passes/{job_id}` | пасы: кадры release/catch, направление, ToF, метрики, точки px |
| GET | `/api/v1/trajectories/{job_id}` | точки траекторий (px + метры физмодели) |
| GET | `/api/v1/rallies/{job_id}` | розыгрыши и их фазы |
| GET | `/api/v1/jobs/{id}/video` | готовое видео с траекториями |
| GET | `/api/v1/jobs/{id}/result-video` | то же, при отсутствии — прорендерит |
| POST | `/api/v1/jobs/{id}/render` | принудительный перерендер |
| GET | `/health` | живость |

## Запуск
```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
Тесты: `python tools/make_test_video.py && pytest -q`
(26 тестов: физика, детекция парабол/направлений, рендер, полный E2E-API).

## Конфигурация (env)
`BT_VBALLNET_PATH` — путь к ONNX; `BT_HEATMAP_THRESHOLD` (0.5);
`BT_RALLY_GAP` (15) — разрыв видимости, закрывающий розыгрыш;
`BT_PAR_MIN_FRAMES`/`BT_PAR_MAX_FRAMES` — окно фита параболы;
`BT_PAR_RMSE_FRAC` (0.03), `BT_GRAVITY_FIT_RATIO` (0.55), `BT_GRAV_TOL_REL` (0.75)
— допуски баллистического фита; `BT_MIN_DISP_FRAC` (0.06) — минимальный
горизонтальный перелёт; `BT_RENDER_VIDEO`, `BT_TRAIL_LENGTH`, пути БД/загрузок.
Сетка считается спроецированной в центр кадра по x (калибруется камерой).
