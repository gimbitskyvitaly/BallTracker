# Volleyball Pass Tracking Service

Сервис для отслеживания **траектории паса** на видеозаписи волейбольного матча
с камерой с задней линии. Принцип детекции и модель мяча взяты из репозитория
[asigatchov/fast-volleyball-tracking-inference](https://github.com/asigatchov/fast-volleyball-tracking-inference)
(VballNet, ONNX-инференс последовательности кадров). Конвейер построен по образцу ball time ai:
`видео → детекция мяча → трекинг → очистка от выбросов → классификация пасов → отрисовка`.

## Возможности

- **Детекция мяча** моделью VballNet (`models/*.onnx`) по скользящему окну из `TRACK_LENGTH` кадров.
- **Трекинг** траекторий мяча с матчингом по расстоянию и склейкой разорванных треков.
- **Фильтрация выбросов**: точка `p_i` удаляется из траектории, если
  `||p_i - p_{i-1}|| > eps`, `||p_i - p_{i+1}|| > eps` и при этом `||p_{i-1} - p_{i+1}|| < eps`.
  Если мяч быстро переместился, но в новой точке ведёт себя нормально и не возвращается
  в окрестность предыдущей точки — это не выброс (скорее всего, атака или подача), траектория сохраняется.
- **Классификация паса**. Траектория считается пасом, если она:
  1. имеет **гиперболическую форму** (аппроксимируется гиперболой/параболой с малой ошибкой);
  2. проходит **выше троса сетки**;
  3. идёт **на левый или правый край сетки** (в район антенн).
- **Отрисовка** на исходном видео. Флаг `DRAW_ALL_TRAJECTORIES` выбирает режим:
  рисовать все траектории мяча или только траектории пасов.

## Структура проекта

```
app/main.py              # точка входа сервиса (CLI)
config/settings.py       # загрузка всех настроек из .env
core/detector.py         # ONNX-детектор VballNet
core/tracker.py          # построение траекторий
core/outliers.py         # фильтрация выбросов (правило выше)
core/pass_classifier.py  # критерии паса: гипербола + выше сетки + на край
core/visualizer.py       # отрисовка траекторий поверх видео
core/pipeline.py         # сборка конвейера
scripts/generate_test_video.py  # генератор синтетического тестового видео
tests/test_core.py       # unit-тесты
models/                  # ONNX-модель VballNet
examples/match.mp4       # пример входного видео
.env                     # ВСЕ конфиги сервиса (не игнорируется git-ом по требованию)
```

## Установка

Требования: Python >= 3.9.

```bash
pip install .            # зависимости: numpy, opencv, onnxruntime, python-dotenv
# опционально GPU-инференс:
pip install ".[gpu]"
# для запуска тестов:
pip install ".[dev]"
```

## Использование

Все настройки читаются из файла **`.env`** в корне проекта (переменные окружения
имеют приоритет над `.env`). Достаточно положить видео и модель и указать пути в `.env`:

```bash
python -m app.main                 # запуск полностью из .env
pass-tracker                       # то же самое через console script (ставится pip install .)

# разовые переопределения флагами (не меняя .env):
python -m app.main --video path/to/match.mp4
python -m app.main --model models/VballNetFastV1_seq9_grayscale_233_h288_w512.onnx
python -m app.main --output-dir out/
python -m app.main --draw-all      # рисовать ВСЕ траектории (переопределяет DRAW_ALL_TRAJECTORIES)
python -m app.main --passes-only   # рисовать только пасы
python -m app.main --env-file custom.env
```

Результат пишется в `OUTPUT_DIR` как видео с отрисованными траекториями
(пасы — зелёным, остальные траектории — серым при `DRAW_ALL_TRAJECTORIES=true`).

### Тестовый прогон без реального матча

```bash
python scripts/generate_test_video.py     # создаст examples/match.mp4
python -m app.main                        # прогон конвейера на синтетике
pytest                                    # unit-тесты ядра
```

## Конфигурация (.env)

### Входы/выходы

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `VIDEO_PATH` | `examples/match.mp4` | Путь к входному видео матча |
| `OUTPUT_DIR` | `data/output` | Каталог результатов (видео с траекториями) |
| `MODEL_PATH` | `models/VballNetFastV1_seq9_grayscale_233_h288_w512.onnx` | ONNX-модель VballNet |

### Инференс

| Переменная | Значение | Описание |
|---|---|---|
| `CONFIDENCE_THRESHOLD` | `0.5` | Порог уверенности детекции мяча |
| `TRACK_LENGTH` | `30` | Размер окна последовательности для модели |
| `INFERENCE_DEVICE` | `CPU` | `CPU` или `CUDA` |

### Трекинг

| Переменная | Значение | Описание |
|---|---|---|
| `FPS` | `0` | `0` — брать fps из контейнера видео |
| `MAX_DISTANCE_PX` | `200` | Радиус матчинга точек (масштабируется под ширину кадра) |
| `MAX_DISAPPEARED_FRAMES` | `40` | Сколько кадров трек «живёт» без детекций |
| `MIN_TRACK_POINTS` | `5` | Минимальное число точек для рассмотрения трека |
| `MERGE_GAP_FRAMES` | `40` | Максимальный разрыв для склейки двух треков в один |

### Отрисовка

| Переменная | Значение | Описание |
|---|---|---|
| `DRAW_ALL_TRAJECTORIES` | `false` | `true` — рисовать все траектории мяча; `false` — только траектории пасов |
| `WRITE_OUTPUT_VIDEO` | `true` | Писать ли итоговое видео |
| `TRAJECTORY_TAIL_FRAMES` | `45` | Длина «хвоста» траектории на кадре |
| `SHOW_PER_FRAME_INFO` | `true` | Текстовая информация о пасе прямо на кадре |

### Геометрия сетки (нормализованные координаты кадра: `x/W`, `y/H`)

| Переменная | Значение | Описание |
|---|---|---|
| `NET_GEOMETRY_ENABLED` | `true` | Использовать ли геометрию сетки при классификации |
| `NET_TOP_Y_NORM` | `0.36` | Y верхней тросо-ленты сетки |
| `NET_LEFT_X_NORM` | `0.21` | X левой антенны (левый край сетки) |
| `NET_RIGHT_X_NORM` | `0.79` | X правой антенны (правый край сетки) |
| `NET_CLEARANCE_NORM` | `0.01` | Запас над лентой, засчитываемый как «выше сетки» |

> Для конкретной записи подберите эти четыре координаты по кадру (например,
> открыв любой кадр в редакторе) — они определяют корректность классификации.

### Фильтрация выбросов

| Переменная | Значение | Описание |
|---|---|---|
| `OUTLIER_EPS_RATIO` | `0.05` | `eps` правила как доля ширины кадра |
| `OUTLIER_MAX_ITERATIONS` | `5` | Число проходов итеративной очистки |

Правило: `p_i` — выброс, если `||p_i-p_{i-1}|| > eps` **и** `||p_i-p_{i+1}|| > eps`
**и** `||p_{i-1}-p_{i+1}|| < eps`. Быстрые легитимные перемещения (атака/подача) сохраняются.

### Критерии паса

| Переменная | Значение | Описание |
|---|---|---|
| `PASS_MIN_POINTS` | `6` | Минимум точек в траектории |
| `PASS_MIN_DURATION_SEC` | `0.2` | Минимальная длительность полёта |
| `PASS_APEX_BEFORE_NET_MIN_SEC` | `0.1` | Вершина должна быть до пересечения вертикали сетки |
| `PASS_HYPERBOLA_MAX_RMSE_RATIO` | `0.05` | Макс. RMSE аппроксимации гиперболой (доля высоты дуги) |
| `PASS_REQUIRE_OVER_NET` | `true` | Требовать пролёта выше троса сетки |
| `PASS_NEAR_ANTENNA_MARGIN_RATIO` | `0.12` | Насколько конец траектории должен быть близок к краю сетки |
| `PASS_MAX_CENTER_OFFSET_RATIO` | `0.35` | Ограничение на смещение конца от центра передающей зоны |
| `PASS_MAX_DESCENT_AFTER_APEX_RATIO` | `0.8` | Резкое пике после вершины трактуется как атака/подача |

## Пример минимального `.env` для своего видео

```ini
VIDEO_PATH=data/my_match.mp4

NET_LEFT_X_NORM=0.18
NET_RIGHT_X_NORM=0.82
```
